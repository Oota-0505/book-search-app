# 外出先でスマホ単独で使うための構成案（提案書）

> **⚠️ 2026-09-05 追記: デプロイ先は Cloudflare Workers に決定しました。**
> 本書の「Cloud Run が本命」という結論は、改訂版
> [`workers_migration_plan.md`](workers_migration_plan.md) に差し替えられています。
> 決め手は「カード登録が不要」「コールドスタートがミリ秒」「使い慣れている」の3点です。
> ただし本書の **§1（公開するなら認証が必須）と §4（ミライブの扱い）はそのまま有効**です。

- 作成: 2026-09-05
- 状態: **提案のみ。実装は未着手**
- 前提: 2026-09 に Streamlit → FastAPI へ移行済み（[`migration_report.md`](migration_report.md)）

## 0. 何が問題か

現状の構成は **Mac の上で `run.py` を動かし、Tailscale 経由でスマホから見る**というもの。

```
[スマホ] ──Tailscale──> [自宅のMac: uvicorn] ──> 各図書館・書店サイト
```

この形だと **Mac が起動していないとスマホから使えません**。
外出先で「この本、市の図書館にあるかな」を調べたいときにパソコンを持っていない、
という今回の要件は満たせません。

必要なのは、**Mac に依存しない場所でアプリが動いていること**です。

```
[スマホ] ──HTTPS──> [どこかのサーバー] ──> 各図書館・書店サイト
```

## 1. ⚠️ 先に決めるべきこと：これは「公開」にあたるか

**ホスティングの選定より前に、こちらを決める必要があります。**

[`scraping_monetization_report.md`](scraping_monetization_report.md) と
[`portfolio.md`](portfolio.md) で、すでにこう整理してあります。

> 「個人でグレー」は「公開でもグレー」を意味しない。この非対称性を理解して、
> 本アプリは**個人利用＋コード公開のみ**（デプロイなし）と線を引いた。

インターネット上にURLを置くと、この前提が変わります。

| | 今（Mac + Tailscale） | 素の状態でホスティング |
|---|---|---|
| アクセスできる人 | 自分だけ | URLを知っている全員（検索エンジンにも拾われうる） |
| 相手サイトへの負荷 | 自分の検索回数ぶん | 不特定多数の検索を肩代わりして流す |
| 位置づけ | 私的使用 | 実質的にサービス提供 |

### → 提案：**認証をかけて「自分専用」を保つ**

ホスティングはするが、**自分しか開けない状態にする**。
これなら「Macの代わりに、常時動いている自分のパソコンがある」だけで、
私的使用という位置づけは維持できます。

実装は軽く済みます（いずれか1つ）。

| 方法 | 手間 | 備考 |
|---|---|---|
| **HTTP Basic 認証**（FastAPI に 20 行ほど） | 小 | 一番手軽。PWAでも動く |
| **Cloudflare Access** | 中 | Googleアカウントでログイン。無料枠あり |
| **Cloud Run の IAM 認証** | 中 | スマホのブラウザから使うにはやや不便 |

あわせて `robots.txt` で `Disallow: /` を返し、検索エンジンに載せないようにします。

## 2. ホスティング候補（2026-09 時点で調査）

要件は「**無料 / スマホ単独 / 起動が速い**」。せっかく 6.5 秒 → 0.6 秒にしたので、
**コールドスタートが遅いサービスを選ぶと元の木阿弥**という点が最大の判断軸です。

| サービス | 無料枠 | 停止・復帰 | 起動体感 | 判定 |
|---|---|---|---|---|
| **Google Cloud Run** | 200万リクエスト/月、360,000 GB秒、180,000 vCPU秒（Always Free） | ゼロにスケール | 数秒（小さなPythonコンテナ） | ◎ **本命** |
| **Oracle Cloud Always Free** | ARM VM（4 OCPU / 24GB を常時稼働できる枠） | **止まらない** | **ゼロ**（常時起動） | ○ 速さ最優先ならこれ |
| Koyeb | 512MB RAM / 0.1 vCPU | 1時間で停止 | コールドスタートあり | △ |
| Render 無料枠 | あり | **15分で停止** | **30〜60秒** | ✕ 今回の目的に反する |
| Fly.io / Heroku | **無料枠なし**（2026現在） | — | — | ✕ |
| Streamlit Community Cloud | あり | スリープあり | 遅い | ✕ 移行済みなので対象外 |

### 本命：Google Cloud Run

- **理由**: 無料枠が個人利用には過大なほど大きく（200万リクエスト/月）、
  使っていない間は課金もリソース消費もゼロ。コンテナをそのまま動かせるので
  今の FastAPI アプリを**ほぼ無改造で載せられます**。
- **注意点**:
  - アカウント作成にクレジットカード登録が必要（無料枠内なら請求は発生しない）。
    心配なら**予算アラートを 0 円 / 100 円で設定**しておく。
  - スケールがゼロになるため、久しぶりのアクセスは数秒かかる。
    毎日使うなら実質気になりません。
  - 検索履歴の JSON ファイルは**コンテナが消えると一緒に消えます**（後述）。

### 速さ最優先なら：Oracle Cloud Always Free

- **理由**: VM が**常時起動**なのでコールドスタートが一切ない。
  期限のない無料枠で、性能も十分。
- **注意点**:
  - VM を自分で管理する必要がある（uvicorn の systemd 登録、
    nginx か Caddy で HTTPS、OS のアップデート）。手間は Cloud Run より明確に大きい。
  - ARM インスタンスは人気があり、リージョンによっては
    **「Out of Capacity」で作成できない**ことがあります。

## 3. ホスティングに移すときに必要な変更

今のコードは「自分のMacで動かす」前提なので、そのままでは不都合が出ます。

| 箇所 | 今 | 変更案 |
|---|---|---|
| 検索履歴 | `book_search_app/data/search_history.json` | コンテナは再起動で消える。**ブラウザの localStorage に移す**のが素直（サーバーに状態を持たない） |
| ログ | ローカルのファイルに日次ローテート | 標準出力へ出す（Cloud Run はそれをそのまま収集する） |
| 認証 | なし | §1 のいずれかを追加 |
| ポート | `--port 8000` 固定 | 環境変数 `PORT` を読む（Cloud Run の作法） |
| `robots.txt` | なし | `Disallow: /` を返すルートを追加 |

いずれも小さな変更で、**合計でも半日かからない**見込みです。

### 手順の目安（Cloud Run の場合）

1. `Dockerfile` を書く（10行ほど）
2. `PORT` 環境変数対応と Basic 認証を入れる
3. 検索履歴を localStorage へ移す
4. `gcloud run deploy --source .` でデプロイ
5. スマホの Safari で開いて「ホーム画面に追加」
6. 予算アラートを設定する

## 4. ミライブ（可児市立図書館）の自動判定を戻せるか

### 結論：**「1回のリクエストに減らす」では戻せません。ただし別の正攻法があります。**

#### なぜ回数を減らしても解決しないのか

ご相談の「個人の検索として、1回のアクセス・レスポンスにすれば問題ないのでは」という
考え方について、正直にお伝えします。**回数は論点ではありません。**

これは [`portfolio.md`](portfolio.md) にご自身で整理された内容がそのまま答えになっています。

> スクレイピングとは「**自分のサーバー・プログラムが相手サイトへ自動でHTTPリクエストを送り、
> HTMLを取得・解析する**」行為を指す。
> **robots.txt は自動化されたクローラー・ボット向けの規約であり、人間がブラウザで
> ページを閲覧する行為には適用されない**。

判断の分かれ目は**回数ではなく「誰がリクエストを送っているか」**です。
1回に減らしても、送っているのは依然としてアプリのプログラムであり、
可児市立図書館が `/csp` 配下について明示的に拒否している自動アクセスに当たります。

さらに、岡崎市立中央図書館事件（Librahack事件）の教訓として
ご自身がまとめられたとおりです。

> **自分のアクセスが軽くても、相手のシステムが脆弱なら疑われるのは自動アクセスしていた側**。

同館は 2026-05 に「サーバ負荷軽減」の注記まで追加しており、
**負荷を理由に明示的に断っている相手**です。回数を減らして再開するのは、
「軽くすれば怒られないだろう」という判断であって、意思表示の尊重にはなりません。

#### 戻せる正攻法：カーリル図書館API

**機能そのもの（ミライブの在庫を自動判定する）は、正規のAPIで復活できます。**
これは [`scraping_monetization_report.md`](scraping_monetization_report.md) で
すでに候補として挙げてある道です。

調査した内容（2026-09-05 時点）:

| 項目 | 内容 |
|---|---|
| 費用 | **法人・個人を問わず無償** |
| 対象 | 全国7000以上の図書館 |
| 取得できるもの | 「貸出可」「貸出中」などの**リアルタイムの貸出状況** |
| 制限 | check API・library API とも、**アプリケーションキーごと・IP毎に 1000リクエスト/時** |
| キー | [申請ページ](https://calil.jp/api/dashboard/)から取得 |
| **義務** | 図書館名や「蔵書あり」「貸出可」を表示するときは、**必ずカーリルのページへリンクを貼ること** |
| ポーリング | 応答が `continue: 1` のときは `session` を付けて再問い合わせ。**2秒以上の間隔をあけること** |

エンドポイント: `https://api.calil.jp/check`（必須: `appkey` / `isbn` / `systemid`）

#### ただし、設計変更が1つ必要です

**カーリルの check API は ISBN が必須**です。
今のアプリは「キーワード（書名・著者名）」で検索する作りなので、そのままでは繋がりません。

```
今:    キーワード ──────────────> 各サイトのHTMLを解析
必要:  キーワード ──> ISBN ──> カーリルAPI ──> 貸出状況
                     ↑ここが無い
```

書名から ISBN を引く手段が別途必要になります。調査した範囲では:

| API | 書名→ISBN | 備考 |
|---|---|---|
| openBD | **不可** | ISBN から書誌を引く方向のみ。逆引き機能がない |
| 国立国会図書館サーチ | 可 | 網羅性は高いが、あいまい検索に弱い（「7つの習慣」で正式書名「完訳 7つの習慣」に当たらないことがある） |
| Google Books API | 可 | 表記ゆれに強い。無料枠あり |

そのため実装は「キーワード → 書名候補＋ISBN → カーリルで在庫確認」の
**2段構え**になり、UIも「候補から本を選ぶ」1ステップが増える可能性があります。

#### 未確認事項（要確認）

- **可児市立図書館がカーリルの対象に含まれているか**を、まだ確定できていません。
  カーリルは「全国7000以上」を謳っており公立図書館なのでほぼ確実ですが、
  **断定は避けます**。アプリケーションキーを取得したうえで、以下で確認できます。

  ```bash
  curl "https://api.calil.jp/library?appkey=<KEY>&pref=岐阜県&city=可児市&format=json"
  ```

  ここで `systemid` が返れば対応しています。メディコス（岐阜市立図書館）も同様に確認できます。

#### 提案する順序

1. カーリルのアプリケーションキーを申請する（無料）
2. 上のコマンドで**可児市・岐阜市の systemid を確認**する
3. 対応していれば、ミライブを「リンクのみ」→「カーリル経由で在庫表示」に戻す
   - このとき**カーリルへのリンクを貼る義務**を必ず実装する
4. 余力があれば、メディコス（岐阜市立図書館）も**スクレイピングからカーリルAPIへ移行**する
   - 相手サーバーを直接叩かなくなるので、負荷・規約の両面でリスクが下がります

## 5. まとめ（おすすめの進め方）

| 順 | やること | 目的 | 規模 |
|---|---|---|---|
| 1 | Basic 認証 + `robots.txt` を追加 | 「自分専用」を保つ | 小 |
| 2 | 検索履歴を localStorage へ / `PORT` 対応 / ログを標準出力へ | ホスティング対応 | 小 |
| 3 | `Dockerfile` を書いて **Cloud Run** にデプロイ | **Mac なしでスマホから使える** | 中 |
| 4 | スマホの Safari で「ホーム画面に追加」 | PWAとして常用 | — |
| 5 | カーリルAPIキーを取得し、systemid を確認 | ミライブ復活の可否を確定 | 小 |
| 6 | ミライブ（＋できればメディコス）をカーリルAPIへ | 正規の方法で機能を戻す | 中 |

1〜4 までで「外出先でスマホだけで使える」は達成できます。
5〜6 は独立して進められるので、別日でも構いません。
