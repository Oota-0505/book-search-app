# 書籍横断検索アプリ — スクレイピング適法性・公開/マネタイズ調査レポート

- **調査日**: 2026年7月5日
- **調査方法**: 各サイトの robots.txt をリアルタイム取得、利用規約・サイトポリシーの原文確認、関連判例・代替APIのWeb調査
- **対象**: 岐阜市立図書館（メディコス）/ 可児市立図書館（ミライブ）/ 三省堂書店 岐阜駅店（岐阜駅本屋）/ 草叢BOOKS各務原店（TSUTAYA / T-SITE）

---

## 1. エグゼクティブサマリー

| サイト | 個人利用（現状） | 公開・商用化 | 主な根拠 |
|---|---|---|---|
| ミライブ（可児市立図書館） | ❌ **中止推奨** | ❌ 不可 | robots.txt が検索パス `/csp` を明示的に Disallow |
| メディコス（岐阜市立図書館） | ⚠️ グレー（低リスク） | ❌ 不可（許諾なしでは） | robots.txt なし。サイトポリシーは私的利用の複製のみ許可 |
| 岐阜駅本屋（三省堂） | ✅ ほぼ問題なし | ⚠️ 要許諾 | 検索ページは robots.txt で許可されたまま（2026年7月時点） |
| 各務原BC（TSUTAYA） | ⚠️ グレー | ❌ **不可** | 利用規約 第9条(7) が営利目的行為を明示的に禁止 |

**結論**: 現在の構成のまま「アプリとして公開して収益化」することは**できません**。ただし、
図書館2館を**カーリル図書館API**（無償・商用利用可）に置き換え、書店2店を「リンクで開く」方式に変更すれば、
**合法的に公開・収益化できる構成に作り替え可能**です（→ §5）。

## 2. サイト別の詳細調査結果

### 2.1 ミライブ（可児市立図書館） — ❌ スクレイピング中止を推奨

**robots.txt（2026-07-05 取得、原文）:**

```
User-agent: *
Disallow: /csp


# 2026/05/11 追加: サーバ負荷軽減のためカーリルに流量制限を明示（１秒に１回程度。効果があるかは不明）
User-agent: CALIL
Crawl-delay: 1
```

- アプリがアクセスしている `https://www.kani-lib.jp/csp/opw/OPW/OPWSRCH1.CSP` と `OPWSRCHLIST.CSP` は
  **両方とも Disallow 対象**。
- **2026年5月11日に「サーバ負荷軽減」のコメントが追記**された。図書館側が実際に負荷問題を認識し、
  提携相手であるカーリルにすら流量制限を課している状態。この状況で robots.txt を無視した
  自動アクセスを続けるのは、技術的マナー違反にとどまらず、後述の Librahack 事件型のトラブル
  （業務妨害を疑われる）リスクが最も高いサイト。
- robots.txt 自体に法的拘束力はないが、違反していた事実は民事・刑事いずれでも「悪意の証拠」として扱われやすい。

**推奨**: このサイトへの自動アクセスは停止し、カーリルAPI（可児市の4館に対応済み）へ移行する。
移行までの間は「検索リンクを開く」ボタンだけ残す運用が安全。

### 2.2 メディコス（岐阜市立図書館） — ⚠️ 個人利用はグレー（低リスク）、商用は不可

- **robots.txt**: 存在しない（404）→ クローラー向けの技術的制限はなし。
- **サイトポリシー**（g-mediacosmos.jp/sitepolicy.html）:
  - コンテンツの複製は「個人的にまたは家庭内その他これに準ずる限られた範囲内」のみ許可。
  - それ以外の利用・改変には著作権者の許諾が必要。
  - 外部からのリンクは事前連絡制（リンクポリシーとしてはかなり厳格な運用）。
  - スクレイピングへの明示的言及はなし。
- 在庫の有無・書誌データ自体は「事実」であり著作権の対象外だが、公開アプリとして
  サイトへ自動アクセスさせる行為はポリシーの想定外利用。
- **個人利用**: 1回の検索で2リクエスト程度・低頻度なら実害リスクは低い。ただし図書館OPACである点は §3 の Librahack 事件に留意。
- **公開・商用**: 許諾なしでは不可。カーリルAPI（岐阜市の17館に対応済み）へ移行するのが正解。

### 2.3 岐阜駅本屋（三省堂書店） — ✅ 現実装は robots.txt 準拠

**robots.txt（2026-07-05 取得、原文）:**

```
user-Agent: *
Disallow: /booksearch/BookSearchDetail.action*
Disallow: /booksearch/EBookSearchDetail.action*
Disallow: /booksearch/BookStockList.action*

user-Agent: meta-externalagent
Disallow: /booksearch/
```

- アプリが使う `BookSearchExec.action`（検索実行）は **Disallow されていない** → 現実装は準拠。
- 詳細ページ・在庫リストページは Disallow。**今後の機能追加でこれらのページを取得しないこと**。
- 2024年調査時から Meta のAIクローラー向けルールが追加されており、サイト側が自動アクセスを監視・制御している兆候はある。
- 公開サイト上に一般向けのサイト利用規約は見当たらない（会員規約は別物）。
- **個人利用**: 問題なしと判断できる。**商用化**: 規約がない以上「禁止されていない」が、
  企業サイトのデータを使った収益事業は許諾を取るのが筋であり、無許諾ではブロック・法的請求のリスクを常に抱える。

### 2.4 各務原BC（草叢BOOKS / TSUTAYA / T-SITE） — ⚠️ 個人はグレー、商用は明確に不可

- **robots.txt**: 存在しない（404）。
- **『TSUTAYA online』サービス利用規約**（store-tsutaya.tsite.jp/support/term.html）:
  - **第8条**: 提供される情報は著作権法上の**私的使用の範囲を超えて使用・公開してはならない**。
  - **第9条(7)**: 「当社の承認なく本サービスを通じて、または本サービスに関連して**営利を目的とする行為**」を禁止。
  - 第2条で本サービスに関する一切の関係に適用と規定 → 店舗在庫検索も対象と解釈するのが自然。
- アプリは1回の検索で**最大3リクエスト**（検索→select→在庫）を発行しており、4サイト中最も負荷が大きい実装である点にも注意。
- **個人利用**: 私的使用の範囲内と主張できる余地はあるが、規約の建て付け上グレー。
- **公開・商用**: 第9条(7) に正面から抵触。**不可**。

## 3. 法的な整理（日本法）

1. **スクレイピング自体は違法ではない**。公開ページの閲覧・取得は原則自由で、
   書誌情報・在庫の有無といった「事実データ」に著作権は発生しない
   （著作権法上も、情報解析目的の複製は30条の4等で広く許容される）。
2. **最大のリスクは「業務妨害」**。図書館OPACに対する自動アクセスでは
   **岡崎市立中央図書館事件（Librahack事件、2010年）**という直接の前例がある:
   - 利用者が新着図書ページを**約1秒に1回**クロール（約2週間で3.3万リクエスト）
   - 図書館側システムの欠陥が原因でサイトが閲覧困難になり、利用者が**偽計業務妨害容疑で逮捕**（20日間勾留、起訴猶予）
   - 技術的には常識的なアクセス頻度でも、相手方システムが脆弱だと刑事事件に発展し得る、という教訓
   - 本アプリの対象はまさに地方の図書館OPAC（しかも可児は負荷問題を自認済み）であり、この前例が最も重い
3. **利用規約違反は民事リスク**。規約に同意した会員でなくても、公開された禁止事項に反する利用は
   不法行為・債務不履行構成で損害賠償や差止の対象になり得る。少なくともアクセスブロックは正当化される。
4. **不正アクセス禁止法は非該当**(現構成ではログイン・認証回避をしていないため)。
5. **個人利用と公開の非対称性**: 自分ひとりが手動検索の代わりに使う分のアクセス量と、
   不特定多数のユーザー分のアクセスを肩代わりして発生させる公開アプリでは、
   負荷・規約・リスクの評価がまったく別物になる。「個人でグレー」は「公開でもグレー」を意味しない。

## 5. 公開・マネタイズへの道筋

### 5.1 合法構成への作り替え（必須ステップ）

```
現在:  [Streamlit] ──スクレイピング──> 図書館2館 + 書店2店
公開版: [アプリ] ──カーリルAPI──> 図書館蔵書・貸出状況（全国7,000館）
        [アプリ] ──楽天ブックスAPI/openBD──> 書誌・表紙・価格
        [アプリ] ──リンクアウトのみ──> 書店の在庫検索ページ（スクレイピングしない）
```

- **カーリル図書館API**（calil.jp/doc/api.html）
  - 法人・個人を問わず**無償**、**商用利用可**。アプリケーションキーを無料申請。
  - 岐阜市立図書館（中央図書館ほか17館）・可児市立図書館（カニミライブ図書館ほか4館）とも**対応済みを確認**。
  - ISBN指定で「貸出可 / 貸出中 / 蔵書なし」が取れる = 現アプリの図書館機能の完全上位互換。
  - 注意: ISBNベースなので「キーワード → 書誌（ISBN）」の解決を openBD / 楽天ブックスAPI / Google Books API で先に行う設計になる。
- **書店在庫**: TSUTAYA・三省堂とも公開APIはない。公開アプリでは
  (a) 在庫判定をやめ検索結果ページへの**リンクだけ**にする（法的に最も安全、現在の「結果を開く」ボタンはそのまま活きる）、
  (b) 本気でやるなら各社に提携・許諾を打診する、の二択。

### 5.2 収益化の選択肢と現実性

| 手段 | 仕組み | 現実性 |
|---|---|---|
| **楽天アフィリエイト** | 楽天ブックスAPIの結果にアフィリエイトIDを付与。売上の数%（書籍はおおむね2〜4%） | ◎ 最有力。API利用とアフィリエイトが公式に一体化しており規約面もクリーン |
| **Amazonアソシエイト** | 既存のAmazonリンクをアソシエイトリンク化（書籍3%程度） | ○ 審査あり（180日以内に3件の成果が必要）。PA-APIの利用には売上実績が必要 |
| 広告（AdSense等） | ページ広告 | △ 図書館ユーザー層と相性は悪くないが、相応のPVが必要 |
| 有料アプリ/サブスク | 課金 | ✕ カーリル・各図書館公式が無料で存在するため、支払い動機が弱い |

### 5.3 市場性についての率直な評価

- 「全国の図書館横断検索」は**カーリル自身が既にやっている**ため、単純な蔵書検索アプリでは勝てない。
- 本アプリの本当の差別化は「**図書館2館+書店2店を、自分の生活圏でひとまとめに見られる**」という
  ローカル体験。これを一般化した「自分の街の図書館＋書店を登録して横断検索」はニッチだが独自性がある。
  ただし書店在庫の合法的な取得手段がボトルネック（リンクアウト or 提携が必要）。
- 収益規模の目安: アフィリエイト型は「月間検索数 × クリック率 × 購入率 × 単価 × 料率」。
  地域特化アプリのトラフィックでは**月数百円〜数千円**が現実的なライン。
  「稼ぐ」より「ポートフォリオ・実績として公開し、副次的に小さな収益を得る」と捉えるのが妥当。

### 5.4 推奨ロードマップ

1. **Phase 0（すぐ）**: ミライブのスクレイピング停止（リンクアウト化）。個人利用は現状の他3サイトで継続。
2. **Phase 1**: カーリルAPIキー取得 → 図書館2館をAPI移行（キーワード→ISBN解決に openBD/楽天API を併用）。
3. **Phase 2**: 書店をリンクアウト専用に変更 → この時点で**公開可能な構成**になる。Streamlit Community Cloud で無料公開。
4. **Phase 3**: 楽天アフィリエイト・Amazonアソシエイト審査 → リンクを収益化。
5. **Phase 4（任意）**: 「町を選んで図書館＋書店を登録」汎用化、書店との提携打診。

## 6. コードレビュー結果（2026-07-05 適用分）

### 適用済みの修正

1. **検索履歴ボタンのクラッシュ修正**（`app.py`）
   - ウィジェット生成後に `st.session_state.keyword_input` を書き換えると
     `StreamlitAPIException` が発生する。`pending_keyword` を経由して次回 run の生成前に反映する方式に変更。
2. **検索結果の10分TTLキャッシュ**（`check_all_sites` に `@st.cache_data`）
   - 同一キーワードの再検索（履歴ボタン等）で各サイトへ再アクセスしない。サーバー負荷対策として最重要。
   - 全サイトエラー時はキャッシュを即時破棄し、次回再試行できるようにした。
   - 副作用: 在庫表示が最大10分古い可能性（用途上許容範囲）。
3. **User-Agent にアプリ識別子 `BookFinder/1.0 (personal-use)` を追加**（透明性の確保）。
4. **`.gitignore` に `logs/` を追加**（検索キーワードを含むログの誤コミット防止）。
5. **ミライブのリンクアウト化**: robots.txt（`Disallow: /csp`）と2026年5月の負荷軽減注記を尊重し、
   在庫の自動判定を停止。カードは「🔗 リンクで確認」＋検索結果ページへのリンク提示に変更。
   README にスクレイピングポリシーの節を追加。

### 未対応の指摘（今後の課題）

- `requests.Session` がクローズされていない（`with requests.Session() as s:` 推奨）— 修正は保留中。
- メディコス判定は「ヒットあり = 在庫あり」の粗い判定で、貸出中を区別していない
  （カーリルAPI移行で根本解決するため深追いせず）。
- 各務原BCは1検索あたり最大3リクエスト発行と負荷が大きい（キャッシュ導入で緩和済み、リンクアウト化で根本解決）。
- ログローテーション30日分に検索キーワードが平文で残る。公開時はログ方針の見直しが必要。
